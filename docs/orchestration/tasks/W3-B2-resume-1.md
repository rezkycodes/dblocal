## What the reviewer found by reading `engine/mariadb/mod.rs` (same classes of defects the MySQL adapter had)

### R1 (HIGH) — shutdown signals whatever pid is in the pidfile, and its liveness check is wrong off Linux and for zombies

`shutdown_by_sigterm` reads the pid from the pidfile and sends SIGTERM to it without checking that it is our `mariadbd`. After a crash or reboot the pidfile is stale and the pid can belong to any process of the same user: we would SIGTERM it. Fix: before signalling, verify identity: on Linux `/proc/<pid>/exe` (resolved) equals the runtime's `bin/mariadbd` (or `mariadbd` from `ctx.runtime_dir`), and that its `--datadir`/`--defaults-file` argument names this instance (read `/proc/<pid>/cmdline`); on macOS use `libc::proc_pidpath` through `nix`/`libc` if already a dependency, otherwise `ps -p <pid> -o command=` and say it is unverified; a pid that is not ours is `Ok(())` with a log line, never a signal. `pid_alive` tests `/proc/<pid>` existence: (a) on macOS `/proc` does not exist, so it returns false at once and `shutdown` reports success right after sending the signal without waiting; (b) a zombie (a child that exited and was not yet reaped) still has `/proc/<pid>`, so a mariadbd started by a parent that has not `wait`ed looks alive until the grace ends. Use `kill(pid, 0)` for liveness and treat state `Z` in `/proc/<pid>/stat` as dead. Tests: a pure function for the identity decision (table of exe/cmdline cases), a pidfile pointing at an unrelated live process (`sleep 60` you spawn) must NOT be signalled (assert it is still alive afterwards), a zombie is dead, a real mariadbd is stopped. Mutation: skip the identity check, the unrelated-process test goes red.

### R2 (HIGH) — a socket path over 107 bytes fails instance creation; macOS allows 103

`socket_path(&ctx.data_dir, port)` puts the socket inside the data directory and `validate_socket_path_len` rejects more than 107 bytes. Same defect as MySQL (see `tasks/W3-B1-fix-1.md` P1 for the reasoning): the macOS limit is 103, a macOS home path is long, and PostgreSQL's adapter falls back instead of failing. Implement the same behaviour here: a platform limit (107 Linux, 103 macOS/BSD), and when the instance socket path is longer a short private fallback path (`$XDG_RUNTIME_DIR/dblocal/` if set and short, else `/tmp/dblocal-<euid>/`, mode 0700, owned by the current euid, not a symlink; file name from the port and a short hash of the data directory), written into `my.cnf` so `initialize`, bootstrap and start agree. Another worker is writing the MySQL version of this in `engine/mysql.rs` at the same time: do NOT touch that file and do not create a shared module; write yours under `engine/mariadb/`, the reviewer will merge the two into one helper afterwards. Real-binary e2e: an instance inside a deliberately deep temporary directory (socket path over 120 bytes) starts, accepts a TCP login, stops, and the fallback socket is gone.
