## T2 (MEDIUM hardening) — the cleanup deletes whatever `socket=` names

`cleanup_fallback_socket_from_my_cnf` reads `socket=` from `my.cnf` and `fs::remove_file`s that path unless it equals the run-dir socket. Today my.cnf is generated by us, but the Config tab (F-CFG) will let a user edit configuration, and a wrong `socket=/home/me/notes.txt` would be deleted on every shutdown and failed initialize. Delete only when ALL hold: the parent directory is one of `fallback_socket_dir_candidates()`, the file name matches `m<port>-<12 hex>.sock` for THIS port, and `symlink_metadata(..).file_type().is_socket()` (unix). Otherwise log `tracing::warn!` and leave it. Tests: a regular file with a valid fallback name is NOT deleted; a socket with a foreign name is NOT deleted; a real `UnixListener` socket with the right name and parent IS deleted; a socket of another port is NOT deleted. Mutation: drop the `is_socket` check -> the regular-file test goes red.

## T3 (LOW) — two decisions that fail late

1. `ensure_fallback_socket_dir` returns the first verified candidate even when `<candidate>/m<port>-<hash>.sock` will not fit, and `resolve_socket_path_with_fallback_dir` then fails instead of trying the next candidate (a long `XDG_RUNTIME_DIR` would block `/tmp/dblocal-<uid>`). Choose the first candidate that is both verifiable and whose resulting socket path fits; fail only when none does, naming each candidate and why it was rejected. Test with a fake long first candidate and a short second one.
2. `effective_superuser` only `debug_assert!`s the identifier: in a release build an unsafe name is interpolated into SQL unescaped. `render_init_sql` returns `Result`: return `InvalidInput { field: "superuser" }` when `!is_safe_sql_identifier(name)` and keep the `debug_assert!` out. Test with `root'; DROP USER x; --`, an empty string (-> default `root`), a name with a dash.
