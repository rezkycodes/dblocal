## Build

1. **Config tab for a selected instance** (`InnerTab::Config`; PostgreSQL, MySQL, MariaDB, Valkey, all from `config_view`, nothing per-engine hard-coded in the GUI except icons): one card "Pengaturan" with a row per setting: label (the key), the current value in an input, the default next to it ("Bawaan: 100"), the unit/typing hint the view gives, the one-line description, a "perlu restart" marker (text, not colour alone). Read-only settings (`port`, PostgreSQL "metode autentikasi") render as plain text with the reason ("Ubah port lewat tindakan Ubah port"; "Dikelola DBLocal, tidak dapat diubah di sini"): this is the deliberate deviation recorded in `config.md`; do not add a control for them. An unset key shows the default as placeholder and the text "bawaan".
2. **Edit and apply.** Edits are local until "Terapkan" (disabled while nothing changed or a call is in flight); validation messages come from the service (`DBL-8601` text); show them under the field and do not close anything; a typed busy error (`DBL-8604`) says to try again. On success show "Tersimpan. Berlaku setelah restart." with the backup time, and a **"Restart sekarang"** button when the instance is running (goes through the existing stop/start path in `service_bridge`, not a new service call) plus "Nanti". "Batalkan perubahan" resets the form. Never log a value; a Valkey `requirepass` is not in the view (do not invent a field).
3. **Restore.** A "Pulihkan konfigurasi sebelumnya" action enabled when `backup_available` is set, with a confirmation dialog that names the backup time and says the current file is kept as a backup too. When an instance's `FailureInfo.restore_available` is true, the Overview failure banner and this tab both offer "Pulihkan konfigurasi dan mulai ulang" (F-CFG-01 AC3: it must be reachable from where the failure is shown); restoring then starting is two service calls, report either failure typed.
4. **Open the raw file** (F-CFG-02 AC1): "Buka file konfigurasi" calls `config_open_raw`; show the path with a Copy button always (the launcher can fail: `DBL-8608` is shown as a typed message with the path, never a panic), and the missing-file `DBL-8607` message.
5. **Events and state.** Refresh on `ServiceEvent::ConfigChanged` for the visible instance (another window, the CLI, a restore), without discarding unsaved edits to other keys (show "File berubah di luar aplikasi" and re-base only the untouched fields). The tab state is keyed by instance id (switching instances never shows another instance's values). Every call off the GPUI thread through `service_bridge`, buttons disabled and labelled while in flight.
6. **Strings and a11y.** All text in `strings.rs`, Indonesian as the PRD writes it. Text through `Label`; unique element ids derived from instance id + key (the a11y duplicate-node assertion is the trap: a test with two instances sharing the same keys); keyboard: Tab follows the visual order, `Enter` in a field applies only when Terapkan is enabled, `Escape` closes the restore dialog; status never by colour alone.
7. **Mock**: scripted scenarios for the screens and tests (all four engines' views, an invalid value, a busy call, a slow call, a failed apply, a restore available, no backup, a launcher failure, a `ConfigChanged` arriving mid-edit).
