## Goal

DBLocal looks and behaves like the user's prototype, on top of the architecture that already exists: `ShellState`, `Tabs`, `LogStore`, `service_bridge`, `format`, `strings.rs`, the mock service and the tests. The prototype's `model.rs` and its sample data are NOT ported: views render `InstanceView`, `CatalogView`, `Runtime` and the events of the frozen service. Nothing is invented in the product build.

## You own

`crates/gui/**`, `crates/core/src/service/mock/**` (seed data and scripted scenarios only), `crates/core/src/strings.rs` (only editor in this task), `docs/design/UI-DIRECTION.md` (rewrite it so it describes the prototype-based UI, keep the contrast rules), `docs/design/renders/**`, `docs/architecture/gui.md`. ## What to build (match the prototype, screen by screen)

1. **Theme.** `DBLocal Dark` from `themes/dblocal.json` (base `#15161d`) becomes the default dark theme. Create `DBLocal Light` in the same visual language (D-23/F-PLH-02 need both; the app follows the system theme, keep W1-G's switching). The existing contrast test must read the real theme JSON files and pass 4.5:1 for every text and control pair in both themes. If a prototype colour fails, lighten or darken it the minimum amount, keep the hue, and list each change with before and after ratios in `docs/design/UI-DIRECTION.md`. No colour literals in views: use theme tokens.
2. **Title bar.** App mark, "DBLocal", breadcrumb `Engine > instance` of the selected tab, catalog freshness on the right (`Fresh`, `Stale`, `Offline` from `CatalogView`, in Indonesian), a "+" for a new instance, window controls per platform as the prototype does.
3. **Instances dock.** Header `INSTANCES` with "+", filter input, collapsible engine groups with counts, rows with status glyph and text (not colour alone: running, stopped, failed, busy), name, version, `:port` (a failed row shows its port in the danger colour). `RUNTIMES` section from `list_runtimes` (name, version, instance count, "tak terpakai" when unused). Primary "Instance baru" button at the bottom. Selection, keyboard navigation and focus order explicit.
4. **Tabs and header.** One tab per opened instance with the status glyph and a close button; instance header with engine monogram badge, name, status chip, subtitle (`Engine version, 127.0.0.1:port, state, detached`), actions Start/Stop, Restart, "Open in..." (dropdown). A transitional state shows the busy glyph and disables the action. Sub-tabs Overview, Logs, Databases, Config.
5. **Overview.** Cards: Connection (masked URI with Show/Hide, Copy URI, Copy .env through `connection_uri(UriFormat)`, the `.env` block, the "127.0.0.1 only" note, credential location), Detail (engine, superuser, port with canonical marker, data dir, data size via `data_size`), Process (PID, health, process mode "detached, stays alive when the app closes", credential reference, autostart checkbox through `set_autostart`). Passwords are `SecretString` end to end: never rendered, logged or put in a `Debug` impl; the URI is fetched only on demand and cleared from view state on hide and on tab close.
6. **Logs.** Log view from `LogStore` (per instance buffer, live follow with a real scroll handle, already built in W1-G), plus the diagnosis banner for a failed start (F-LOG-02) with the one-click action "Pindah ke port berikutnya & start" implemented as `suggest_port` + `change_port` + `start_instance`, shown only when the failure is the typed port-in-use error.
7. **New instance dialog.** Engine cards (monogram, name, canonical port), version list from `CatalogView` with the "Terpasang" / "Unduh, size" badges, name, port and superuser fields with the prototype's inline hints and validation through `validate_spec`, the no-password option with its warning, footer text "Akan mengunduh runtime lalu verifikasi SHA-256" shown only when a download is needed, Batal / Create. Unavailable engine or version for this platform is shown as "tidak tersedia di platform ini" (F-CAT-02 AC2), not hidden and not an error.
8. **Status bar.** Counts (running, stopped, failed), data directory and total size, credential backend, `os arch`, app version; plus what W1-G already shows (active downloads with the popover, offline banner, tray unavailable note).
9. **Keyboard.** `Ctrl/Cmd+N` new instance, `Ctrl/Cmd+Shift+C` copy URI, `Ctrl/Cmd+Enter` start/stop, and W1-G's `Ctrl/Cmd+K` command palette, which stays.
10. **Keep what the prototype lacks**, restyled in its language: command palette, delete instance (Archive default / Purge, F-INS-05, D-18), toasts with DBL codes, offline and stale banners, download progress and cancel, welcome empty state.
11. **Honest placeholders.** The Databases tab (F-DBU, Phase 2), the Config tab (F-CFG, Phase 3) and "Open in..." (F-OPN, Phase 2) have no backend in the frozen service. In the product build they render the prototype layout with a clear Indonesian "belum tersedia di versi ini" state and disabled controls, never sample rows. The prototype's sample content (databases, users, config values) may appear only in the mock/demo build, so that the layout is reviewable. Every such placeholder is listed in `docs/architecture/gui.md` with the phase that fills it.
12. **Mock seed.** Extend the mock's demo seed to the prototype's scenario (a running `pg-app`, a stopped `pg-legacy`, a failed `pg-shop` with a port conflict, `cache-dev`, `laravel-hr`, `wp-blog`, one unused runtime, a download in progress) so every screen is renderable headlessly.
13. **Strings.** Every sentence in Indonesian in `strings.rs`, none literal in `crates/gui`. The prototype hard-codes its strings in views; move them.

## Rules that do not bend

No `DblService` call on the GPUI thread is introduced by this task (W2-B makes the existing ones background calls; do not add new blocking calls and do not make the existing ones worse). No timer while idle (OPEN-08). Accessibility: text through `Label` (not bare strings), status never by colour alone, visible focus, no hover-only actions, secondary commands in `DropdownMenu`/`ContextMenu`, per Kit's design guide; list each guide rule you checked in the audit table in `docs/spikes/gpui-kit/README.md` (extend W2-D's table). No `unwrap`/`expect` outside tests, files < 800 lines (the prototype's `pages.rs` is 669 and `workspace.rs` 638, so split by screen), functions < 50 lines except pure layout.
