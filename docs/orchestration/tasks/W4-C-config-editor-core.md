## Research first (rule 0), and write the answers into `docs/architecture/config.md`

1. **Which file is the user's and which is DBLocal's?** Today each adapter RENDERS its config at initialize and rewrites only the lines it manages: `postgresql.conf` in the data dir (port/socket via `sync_port`), `valkey.conf` in the run dir (port line; it can carry `requirepass`), `my.cnf` in the run dir (port, socket, tmpdir, log; written by `write_my_cnf`, rewritten by `sync_port`). Confirm for each engine that nothing regenerates the file on `start` and overwrites a user edit; if any adapter does, say so and fix the adapter to merge instead (that is in scope).
2. **How a user edit coexists with the managed lines.** Rule from the PRD: "komentar serta baris yang tidak dikenal app tidak pernah ditulis ulang atau dihapus". Design a line-level editor, not a parse-and-re-render: change only the one line of a key the user edited (the last uncommented assignment wins, as the engines read it), append `key = value` at the end (inside `[mysqld]` for MySQL/MariaDB) when absent, never reorder, never touch comments, unknown keys, blank lines, line endings (CRLF stays CRLF) or a trailing-newline-less last line. Keys DBLocal manages itself (`port`, `socket`, `tmpdir`, log paths, `unix_socket_directories`, `listen_addresses`, `requirepass`, `datadir`, `bind`, `dir`, pid paths) are NOT editable here (typed error): `port` goes through the existing `change_port`.
3. **Defaults and units.** For each key in the subset below, the default shown to the user must come from the real engine, not from memory. PostgreSQL: `postgres --describe-config` works offline (or `pg_settings.boot_val` on a running instance); MySQL/MariaDB: `mysqld --no-defaults --verbose --help`; Valkey: the shipped `valkey.conf` / `valkey-server --help` and the docs. Put the defaults in a static table with the engine version it was checked against, and add an `#[ignore]` e2e that compares the table with the real engine (so a catalog bump that changes a default is caught).

## Do

1. **Subset (F-CFG-01 AC1).** PostgreSQL: `max_connections`, `shared_buffers`, `work_mem`, `timezone`, plus the read-only `port` and `authentication method` (see 4). MySQL/MariaDB: `max_connections`, `innodb_buffer_pool_size`, `sort_buffer_size`, `time_zone` (as `default-time-zone`), `character-set-server`, read-only `port`. Valkey: `maxmemory`, `maxmemory-policy`, `appendonly`, `save`, `timeout`, read-only `port`. Each setting has: key, current value (what the file says, or "default" when unset), default value, type and range or the allowed set, unit, whether a restart is needed (all of these: yes, say so per key), a one-line description from `strings.rs` (Indonesian). Validation per type before anything is written: integers in range, sizes with the engine's units (`128MB`, `1GB`), booleans, enums, an IANA timezone that exists (use `chrono-tz` or the engine's own list if it is already a dependency; check `cargo deny`), values with no newline, no NUL, no `#`-injection (a value that would turn the rest of the line into a comment or a second directive is refused). Hostile corpus test as W3-A did for identifiers.
2. **API on `DblService`** (add to the trait, `LocalService`, the mock and the demo): `config_view(id) -> ConfigView` (settings as above + `backup_available: Option<BackupInfo { taken_at }>` + `raw_path` + `restart_required: bool`), `config_apply(id, Vec<(key, value)>) -> ConfigApplied { restart_required, backup: BackupInfo }` (atomic: validate everything first, then one write; unknown or unmanaged key refuses the whole call), `config_restore(id)`. A running instance is allowed (the change is for the next start; `restart_required = true`), `delete`/`start`/`stop` in flight refuses as busy (take the per-instance guard: see `LockKind`, `Ops::lock_instance`; this is the guard W4-A's admin calls lack, do not copy that gap). Emit `ServiceEvent::ConfigChanged { id }`.
3. **Backup and restore (F-CFG-01 AC3).** Before every write, copy the file as it is now to `<dir>/dblocal-backups/<instance>/<file>.<unix-ts>.bak` (`0700` dir, `0600` files; `valkey.conf` may hold `requirepass`: the backup is as secret as the file, never logged, never in an error or event). Keep the last 5. `config_restore` puts the newest backup back atomically (and keeps the file it replaces as a backup too, so a restore is undoable). Offer it where the PRD wants it: when `start_instance` fails and the file changed since the last successful start, the failure carries `restore_available = true` (a field on the typed failure the GUI already receives; do not change its shape for other callers: additive, defaulted). Track "last successful start" with a marker next to the backups (file hash recorded when an instance reaches Running), not by comparing mtimes.
4. **Authentication method is read-only in this task.** Show the current method (`pg_hba.conf` host lines for the DBLocal-managed ones) but do not edit `pg_hba.conf`: changing it can lock the user out of an instance whose credential DBLocal holds. This is a deliberate deviation from F-CFG-01 AC1's wording ("metode autentikasi" is listed in the form); say it in the report and in `config.md` so I can take it to the user.
5. **F-CFG-02 AC1.** `config_raw_path(id)` returns the path; the open-in-editor part goes through the existing `open` machinery used by W4-A (`DblService` open calls) with the OS default handler (`xdg-open` / `open` / `cmd /c start`), launched detached, argv only, no shell. Nothing here rewrites the file.
6. **CLI** (`crates/cli/src/commands/config.rs`, Indonesian help like the other commands): `dblocal config show <name> [--json]`, `config set <name> key=value [key=value...]` (prints "perlu restart" and the backup path), `config restore <name>`, `config path <name>`. Exit codes and error printing as the other commands.
7. **Docs and registry.** `docs/architecture/config.md` (the research answers, the line editor rules, the managed-key list per engine, the backup layout, the secret handling), codes 8600-8699 in `error-codes.md`.
