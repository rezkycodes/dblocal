## The defect (the reviewer read it; confirm it first)

`catalog/engines.json` lists MySQL and MariaDB for `windows/x86_64` (and the PRD targets Windows). After the W4-A2 follow-up `MysqlTarget` (`crates/core/src/admin/mysql.rs`) carries no port and `opts()` ALWAYS sets `.socket(Some(path))` + `.prefer_socket(true)`. In `mysql_async` 0.37.1, `Conn::new` (`src/conn/mod.rs:1029-1034`) does `if let Some(_path) = opts.socket() { #[cfg(unix)] connect_socket(..) #[cfg(not(unix))] return Err(DriverError::NamedPipesDisabled) }`. So on Windows every `list_databases`, `create_database`, `drop_database`, `create_user`, `reset_superuser_password` for a MySQL or MariaDB instance fails with `DBL-8100` "Tidak dapat terhubung" (and `mysqld` on Windows does not create a unix socket at all). It fails safe (no silent TCP to a foreign `127.0.0.1:3306`), but F-DBU-01..03 is dead for two of the four engines on one of the three platforms. W4-A2 originally allowed "loopback TCP only if the socket is unavailable"; the follow-up removed it for good on every platform.
