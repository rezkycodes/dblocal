# W4-A2 — MySQL and MariaDB database/user administration behind `DblService` (F-DBU-01..03 for the MySQL family)

Start only after `W4-A fix 1` is merged (it changes `executor_for` and the "not supported" messages in `crates/core/src/instance/admin_ops.rs`; check `git log main --oneline | head`). New branch from main, worktree under `~/orca/workspaces/db-local/`. Rules: `docs/orchestration/tasks/_COMMON-RULES.md` incl. 11-14. You do NOT touch `crates/gui/**`.

## Situation

W4-A put PostgreSQL administration behind `DblService` (`crates/core/src/instance/admin_ops.rs`, the `AdminExecutor` trait, `pg_admin_factory`). For MySQL and MariaDB the same calls return the typed "not supported for this engine yet" error: `list_databases`, `create_database`, `drop_database`, `create_user`, `reset_superuser_password` (and `list_users`). The SQL builders already have the MySQL dialect (`crates/core/src/admin/sql.rs`, backtick quoting, hostile corpus); only the executor and the wiring are missing. Read `docs/architecture/admin.md`, `docs/architecture/service.md` and the W3-B1 / W3-B2 adapter code (`crates/core/src/engine/mysql/`, `engine/mariadb/`) for how the root account, the socket and the bootstrap work.

## Do (read and research first: rule 0)

1. **Client library.** Pick one MySQL/MariaDB client crate that passes `cargo deny` (licenses, advisories) and the "no OpenSSL / no native TLS" stance the workspace already has; justify it in the first commit (candidates: `mysql_async`, `mysql`; check feature flags, TLS, maintenance, binary size). It is only ever used against loopback. **Known trap:** MySQL 8.4 defaults to `caching_sha2_password`; over plain TCP without TLS the server refuses the full authentication unless the client requests the RSA public key, over the unix socket it counts as a secure channel. Prefer the instance's socket (the adapters already resolve it, including the long-path fallback dir); use loopback TCP only if the socket is unavailable, and say which you chose and why. MariaDB 11.x: check which authentication plugin the bootstrap leaves on the root account (W3-B2 report and `engine/mariadb/mod.rs`) and test against it, do not assume.
2. **Executor.** A `MysqlAdmin` (name it as the module you add suggests) that implements the existing `AdminExecutor` trait for both engines: list databases with owner-less size (information_schema, exclude `mysql`, `sys`, `information_schema`, `performance_schema`), create database with `utf8mb4` / `utf8mb4_unicode_ci` (PRD F-DBU-01 AC2; assert it in the e2e), drop database (refuse system schemas, the `force` flag semantics as the PostgreSQL executor), create user + grant (`ro` = SELECT on `db`.*, `rw` = the usual data privileges on `db`.* without GRANT OPTION or global privileges; document the exact privilege list in `docs/architecture/admin.md`), drop user (rollback of a half-created user, as W4-A), reset the superuser password with the F-DBU-03 AC2 guarantee (new password applied and verified by a fresh connection BEFORE the keychain write; on any failure the old password still works and the keychain is untouched). Passwords never in argv, events, logs, errors or `Debug` (canary test as W3-A). Identifiers go through the existing `Identifier` allowlist and the backtick quoter; values (user, password literals) must be bound or escaped by a function with its own hostile-input tests, never string-formatted raw.
3. **Wiring.** `executor_for` selects the executor by engine; the `AuthMode` gate and the new no-password message from W4-A fix 1 stay. Valkey keeps the typed "not supported" error (no named databases or login roles). A per-engine test asserts the error for Valkey and the success path for MySQL and MariaDB through `LocalService` with the fake executor; the mock (`service/mock`) already implements the surface, extend it only if a MySQL-specific behaviour needs it.
4. **Real-engine e2e** through the public `DblService` (extend `crates/core/tests/service_admin_e2e.rs` or add `service_admin_mysql_e2e.rs`, `#[ignore]`d, under the e2e lock, ports 20000-29999, cleanup of every `mysqld`/`mariadbd` even on panic): on real MySQL 8.4.11 and real MariaDB 11.8.10 (the W4-E support module installs the `libcrypt.so.1` shim MariaDB needs on this host: `crates/core/tests/support/mariadb_shim.rs`, reuse it): create database with the charset assertion, list with sizes, drop with the engine refusing a system schema, ro user can SELECT and not INSERT, rw user can INSERT and cannot create another database, password reset updates engine + keychain + URI and the old password stops working, failed reset keeps the old password working. MariaDB 11.4 is catalogued but cannot run on this host (libcrypt); say so plainly.
5. **CLI.** The W4-A commands (`db`, `user`, `password reset`) already call the service; verify them against real MySQL and MariaDB instances with the real binary in an isolated `DBLOCAL_HOME` and paste the transcript. Fix only what is MySQL-specific.
