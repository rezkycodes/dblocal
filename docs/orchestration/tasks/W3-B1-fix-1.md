## P1 (HIGH, deterministic failure on macOS and on long home paths) — a long socket path makes instance creation fail

`validate_socket_path_len` returns `InvalidInput` when `<run_dir>/mysqld-<port>.sock` is longer than 107 bytes, and `initialize` fails. Two problems: (a) the limit is Linux's. `sun_path` is 104 bytes on macOS and the BSDs, so the usable length there is 103; (b) the PostgreSQL adapter (`engine/postgres.rs::choose_socket_dir`, documented in `engines.md`) deliberately does NOT fail creation for a too-long socket path, it falls back. A macOS instance directory such as `/Users/<name>/Library/Application Support/DBLocal/instances/<name>/run/mysqld-42000.sock` is easily over 103 bytes, and the user cannot shorten it, so on macOS (and on Linux with a long username or a deep `XDG_DATA_HOME`) a MySQL instance could never be created. mysqld has no "no unix socket" switch (unlike PostgreSQL's empty `unix_socket_directories`), so the fallback is a SHORT private socket directory.

Fix: `socket_path_limit()` = 107 on Linux, 103 on macOS/BSD (`cfg`); when the run-dir socket path is longer, use a short fallback socket path under a private directory you create (`$XDG_RUNTIME_DIR/dblocal/` if set and short enough, else `/tmp/dblocal-<euid>/`; mode 0700, owned by the current euid, not a symlink, verified the way `clients/terminal.rs::verify_secure_dir_for` does it, file name derived from the port and a short hash of the instance directory so two instances never collide), write THAT path into `my.cnf` `socket=`, and make `initialize`, the bootstrap and `spawn_command` read the same `my.cnf` so they agree. `shutdown` and health use TCP and are unaffected. Fail with the existing `InvalidInput` only if even the fallback does not fit. Tests: pure tests for the limit per platform and for the fallback-path choice (long run dir -> short private path, short run dir -> unchanged); and a REAL-binary e2e that creates the instance inside a deliberately deep temporary directory (run-dir socket path > 120 bytes), starts it, logs in over TCP, stops it, and asserts that the fallback socket is gone afterwards and the fallback directory is 0700. Document the macOS limit and the fallback in `engines.md` and say "unverified on macOS" (you cannot run it here); the reviewer adds the Windows/macOS checklist row.
