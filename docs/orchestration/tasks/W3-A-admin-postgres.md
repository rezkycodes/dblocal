Branch `w3-admin` from `main`. Read `docs/orchestration/tasks/_COMMON-RULES.md` first. PRD: **F-DBU-01..03** (read the business rule: identifier quoting and allowlist, never raw string concatenation; the tab never shows table contents), `F-CRD-01..03`, `docs/architecture/secrets.md`, `docs/architecture/engines.md`, `docs/architecture/e2e.md` (how real PostgreSQL is run in tests), D-18, D-24. Core-only: `CARGO_TARGET_DIR=$HOME/.cache/dblocal-target`. PostgreSQL install from the real tarball works on `main` since the W2-F merge (253 hard links fixed).

## Goal

The engine-facing half of the Databases tab: list databases with sizes, create (UTF-8) and drop databases, create users with read-only or read-write rights on chosen databases, reset the superuser password with the rollback guarantee. It is a LIBRARY over a connection description; wiring into `DblService`, the instance service and the GUI is a later task after the MySQL adapters and the GUI wiring land, so do not touch those.

## You own

## Requirements

1. **Pure layer first** (`admin::sql`): an identifier newtype validated against `[A-Za-z0-9_]` (and a maximum length, and not empty, and not starting with a digit where the engine forbids it, and not reserved names like `postgres`, `template0`, `template1`), a quoting function per dialect (`Dialect::Postgres` and `Dialect::MySql`; implement and unit-test BOTH builders as pure functions now, the MySQL one is executed in a later task), and builders for create database, drop database, create user, grant/revoke by privilege level (read-only = CONNECT + USAGE + SELECT on tables and default privileges; read-write adds INSERT/UPDATE/DELETE and sequence rights; write the exact SQL in the doc), alter password. Anything that can be a bound parameter is one; identifiers and `CREATE ROLE ... PASSWORD` literals are quoted by the tested function. A hostile corpus (quotes, `;`, comments, unicode, null bytes, very long, leading dash, `\`) must be rejected by validation or quoted so that the generated statement parses to exactly one statement of the expected shape: assert it by parsing the statement with a tiny tokenizer in the test or by running it against the real server in the e2e.
2. **Execution** (`admin::postgres`): `AdminTarget { host: 127.0.0.1 only, port, superuser, password: SecretString }`; connect over TCP with a connect and statement timeout, `list_databases` (name, size, owner; exclude templates), `create_database` (UTF8, template0 so the encoding is honoured), `drop_database` (typed error if connections exist, never `FORCE` unless a flag says so), `create_user` (returns the generated password ONCE as `SecretString`; strong generation, no logging), `grant`/`revoke`, `list_users`. The host must be loopback: anything else is a typed error.
3. **Reset superuser password** with the F-DBU-03 AC2 guarantee: generate new, `ALTER ROLE` it, verify a NEW connection authenticates with the new password, then call a `CredentialSink` trait (`store(new)`; the real one is the keychain, injected by the later wiring) and if the sink fails, roll the engine back to the old password and return a typed error; if the engine step fails nothing else changes. Test every failure point with injected failures (including a sink that fails and a rollback that also fails: the error must say the state is inconsistent and carry what the operator needs, never the secrets).
4. Every error is typed with a stable `DBL-xxxx` code and an Indonesian user message; SQL text, passwords and connection strings never appear in `Debug`, `Display`, logs or error chains (prove with a test that formats every error variant and scans for a canary secret).

## Tests and bar

The pure layer is >= 90% covered with the hostile corpus. `#[ignore]` e2e against a REAL PostgreSQL (the latest catalog version, through the same real runtime install the W2-C suite uses, temp home, port in 20000-29999, guard that kills the engine even on panic): create database, appears with a size, UTF8 confirmed from `pg_database`, a read-only user can SELECT but not INSERT, a read-write user can, drop requires no connections, hostile names are rejected BEFORE any statement reaches the server (assert with the server's statement log or a counter), reset password success and each injected failure. Three consecutive e2e runs, paste the summaries. Mutation checks: weaken the allowlist, drop the quoting of one identifier, remove the rollback, grant write on a read-only level; each must fail a named test (paste red output). Then the common bar.
