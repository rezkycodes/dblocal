# W2-B2 evidence — duplicate a11y node id

All output below is pasted from real runs on this machine (Linux/Xwayland,
`DISPLAY=:0`, AT-SPI `IsEnabled` = `(<true>,)`), debug profile.

## Root cause (from gdb at the failing assert)

`gpui-component`'s `Label::new` derives its element id from the caller's
source location. A single call site rendered as several **siblings under one
parent** hashes to one `GlobalElementId`, so gpui's a11y builder sees a
duplicate. gdb, stopped at `gpui-pre-0.3.12/src/window/a11y.rs:415` in the real
debug binary, printed the colliding path:

```
.../root/status-bar/gpui_component::label::Label/CodeLocation(
    crates/gui/src/app/status_bar.rs:134:16)
```

That is `count_pill`'s `Label::new(format!("{count} {label}"))`, rendered once
for "berjalan" and once for "berhenti". Our code, not the dependency.

```
    ~/.cache/dblocal-target-gui/debug/dblocal

```

`#4375755302221953578` is exactly the id in the task's evidence.

`crates/gui/tests/a11y_tree.rs` (with `tests/support/a11y_platform.rs`, a

does, which is why the other tests never saw this):

Split into one `#[test]` per screen, all 19 cases failed before the fix; gdb on
the test binary again named `status_bar.rs:134` and, after that fix,
`dock.rs:242` (the runtime list) and `overview.rs:154/155` (the `.env` rows) —

## Real window, tray Quit (the repro path from the task)

Isolated home `/tmp/w2b2-rw`, one Valkey 9.2.0 instance created and started
(`pgrep -x valkey-server` = 1), the SNI host registered the tray
(`org.kde.StatusNotifierItem-<pid>-1`). Quit was driven through the tray's
DBus menu item 7 "Keluar" (the same action a left-click on the tray runs).

The quit dialog opened and the live AT-SPI tree (pyatspi) showed it, with no
panic:

```
     button 'Batal'
     button 'Hentikan semua lalu keluar'
     button 'Biarkan tetap berjalan'
   label '1 berjalan'
```

## Not verifiable here

Windows and macOS accessibility trees. The `A11yPlatform` wrapper is Linux
headless-only (`gpui_kit::platform::current_platform(true)` there is the
Linux backend), and the real-window pass used X11 + AT-SPI on this host.
