## 3. Recommended `EngineAdapter` implementation outline

Derived from measured behavior (not speculative). All bind addresses loopback-only; all ports validated 41000-41999 in tests (canonical 5432/6379 never used). Never signal by PID without exe+starttime validation.

### 3.1 PostgreSQL

- **Runtime selection / preflight:** `bin/postgres --version`; confirm glibc >= floor (>=2.34 for theseus-rs gnu 18.x) and `ldd` resolves (normally 0 missing). Strip prefix `postgresql-<ver>-<target>/`.
- **Init (`initdb`):**
  - `initdb -D <dataDir> -U <superuser|postgres> --encoding=UTF8 --locale=C.UTF-8` (fallback `C.utf8`, then `C` if unavailable). `--auth-local=trust --auth-host=scram-sha-256` (or trust/trust for "no password" mode) with `--pwfile=<0600 tmp>` when a password is set. Capture stdout/stderr; on failure, remove the partial data dir and surface the raw output.
  - Post-write config: `listen_addresses = '127.0.0.1'` (or `'127.0.0.1,::1'` deliberately), `port = <port>`, `unix_socket_directories = '<shortSockDir>'`. Ensure `<shortSockDir>` exists and that `len(<shortSockDir>/.s.PGSQL.<port>) <= 107`; prefer a short root (not a deep per-instance path) or empty/disable unix sockets and use TCP.
  - Store generated password only in keychain/fallback 0600 secret ref, never in config/DB/logs/argv.
- **Spawn:** `pg_ctl -D <dataDir> -l <logfile> -w -t <startTimeoutSec> -o "<extra opts>" start`. This detaches, writes `postmaster.pid`, and waits for readiness. (Alternative: detached `setsid postgres -D ...` — still writes pidfile — but `pg_ctl` is the managed path.) Record `pid` (postmaster.pid line 1), `start_epoch` (line 3), `exe` path, `port`, `datadir`.
- **Health:** fast pre-check `pg_isready -h 127.0.0.1 -p <port>` (rc 0/2). **True readiness:** real protocol query to the target db/user (e.g. `psql -h 127.0.0.1 -p <port> -U <user> -d <db> -Atc 'select 1'` with `PGPASSWORD` env, or a `tokio-postgres` query). Do not treat `pg_isready rc 0` as "db exists / auth ok".
- **Stop:** `pg_ctl -D <dataDir> -m fast -w -t <graceSec> stop`. If it does not exit, escalate (SIGTERM direct → timed wait → SIGKILL) and **log "kill paksa"**. `fast` cleanly terminates clients.
- **PID validation (before any signal):** read pidfile lines (pid, datadir, start_epoch line 3, port, socket, listen). Require: process alive, `readlink(/proc/<pid>/exe)` is the expected `postgres` in this runtime, `/proc/<pid>/stat` starttime-derived epoch matches line 3 (and/or recorded start), `comm == postgres`, datadir/port consistent. On any mismatch treat pidfile as **stale** (never signal); stale+dead-PID is the normal crash case (`pg_ctl status` rc 3) — `pg_ctl start` can recover.
- **State/diagnosis:** tail server log on failure. Map patterns (F-LOG-02): `could not create any TCP/IP sockets` / `Is another postmaster already running on port` / `Address already in use` → port conflict (offer reassign, F-PRT-02); `database files are incompatible with server` + `initialized by PostgreSQL version <X>` → wrong-major datadir; `Permission denied` on `postmaster.pid`/lock → path/permission; `Unix-domain socket path ... is too long (maximum 107 bytes)` / `could not create lock file ".s.PGSQL...lock": No such file or directory` → socket-dir issue; `initdb: error: directory ... exists but is not empty` → bad target; exec/loader errors or never-ready → runtime broken/reinstall. Keep raw lines.
- **URI:** `postgresql://<user>:<percent-encoded-password>@127.0.0.1:<port>/<db>` (percent-encode always). Supply passwords via env/driver, never argv.

### 3.2 Valkey

- **Runtime selection / preflight:** choose variant by host: prefer **`jammy`** (GLIBC_2.34) for widest glibc compatibility, `noble` only if glibc >= 2.38 (or measured safe); verify `libsystemd.so.0`, `libssl.so.3` (OpenSSL 3), `libcrypto.so.3` are resolvable and `ldd` clean. Strip prefix `valkey-<ver>-<variant>-<arch>/`. Use arch token **`arm64`** (not `aarch64`) in download names.
- **Init:** create `<data>`, `<logs>`, `<run>`; render `valkey.conf`: `bind 127.0.0.1 -::1`, `protected-mode yes`, `port <port>`, `daemonize no`, `supervised no`, `pidfile <run>/valkey.pid`, `logfile <logs>/valkey.log` (ensure parent writable), `dir <data>` (must exist), `requirepass <secret>` (or omit per no-auth mode, keeping protected-mode posture explicit), persistence policy (`appendonly yes` + appenddirname/name, or `save ""`/`appendonly no`). Never log secrets.
- **Spawn:** `setsid valkey-server <conf>` with stdio redirected (logfile carries output), record pid/exe/start time. `daemonize no` so the adapter owns the child.
- **Health:** poll `valkey-cli -h 127.0.0.1 -p <port> -a <pw> --no-auth-warning PING` until response is exactly `PONG` (parse RESP/result; **do not trust cli exit code** for auth errors). Timeout ~10 s (observed ready ~34 ms).
- **Stop:** issue `SHUTDOWN NOSAVE` or `SHUTDOWN SAVE` (per durability policy) via cli/RESP and wait for exit (~10–15 ms typical). On timeout: `SIGTERM` (graceful in Valkey — wait), then `SIGKILL`; log forced kill. Expect pidfile removed on clean stop, stale on crash.
- **PID validation:** before signalling, confirm live PID, exe is the expected `valkey-server`, and start time matches recorded/pidfile context (PID-reuse discipline). On mismatch treat as stale.
- **Diagnosis:** on start failure or timeout, **read the logfile tail** (many fatal causes are log-only). Map: `Failed listening on port <p> (tcp), aborting.` + `bind: Address already in use` → port conflict; `bind: Cannot assign requested address` → bad bind; `*** FATAL CONFIG FILE ERROR ***` (with line/reason) → config/dir missing/invalid values; `Can't open or create append-only dir appendonlydir: Permission denied|Not a directory` → data-dir/appendonly issue. Also handle "never became ready" within timeout as a generic failure with log excerpt.
- **URI:** prefer `redis://default:<percent-encoded-password>@127.0.0.1:<port>/0` for client compatibility (`valkey://` also accepted by bundled cli). Percent-encode always; `rediss://` only with TLS configured.

### 3.3 Cross-cutting

- **F-PRT-02:** real bind probe (no `SO_REUSEADDR` for the check), check both stacks as configured, close probe socket before engine start; on conflict reassign and persist.
- **F-LOG-02:** always capture/surface the engine's raw log/stderr lines with stable regex classification and keep the raw tail for unknown cases.
- **Invariants honored in spikes:** loopback only, no writes outside temp dirs (and cache), SHA-256 verified before extract/exec, all children stopped, ports in 41000-41999.
